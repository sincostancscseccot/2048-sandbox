# 2048 Sandbox｜功能与规则设计文档

**版本：** v0.1（产品设计基线）  
**日期：** 2026 年 10 月 13 日  
**状态：** 讨论稿；尚未进入代码实现  
**定位：** 经典 2048 + 高自由度规则沙盒 + 可分叉的完整历史树

> 本文用于固定已经讨论并同意的产品方向，定义建议的默认行为、数据边界、界面结构和分阶段验收标准。文中的“建议默认”并不等于用户已经批准；未明确决定的选项保留为待讨论项。

## 0. 执行摘要与决策状态

### 0.1 已确认的产品要求【确定】

- 游戏包含**正常模式**和**自定义模式**。正常模式保留经典 2048 体验；自定义模式按“2048 沙盒”方向开发。
- 自定义模式以**自由度优先**：棋盘尺寸、数字及概率、技能开关与次数（含无限）为基础，并向高级移动、合并、生成、事件和规则编辑扩展。
- 两个模式都可以**随时保存完整对局状态、导出数据、查看历史**，并从任一历史节点继续产生新分支。
- 历史不仅可撤销，还要显示为可操作的**树状图**；原有分支默认保留。
- 支持**实时试玩预览、配置差异比较、规则配置导入导出**。
- 本阶段**只完成设计文档，不写游戏代码**。

### 0.2 建议采纳的设计原则【建议默认】

1. **单引擎双模式：** 正常模式加载锁定的经典规则，自定义模式加载可编辑规则集。
2. **不可变历史：** 历史节点不原地覆写；修改历史局面或规则，生成新分支。
3. **确定性优先：** 同一状态、同一操作及同一随机状态，结果应一致；非确定因素必须留下记录。
4. **操作与观看分离：** 看旧节点不影响成绩；从旧节点重新行动会创建探索分支并记录来源。
5. **任意玩法≠任意不安全执行：** 允许难以获胜甚至无法合并的配置，但拦截无法计算、数据损坏或无穷执行的规则。
6. **数据可迁移：** 规则、单节点、单分支、整棵时间树和完整项目可以分别导出。
7. **能力渐进呈现：** 常用参数直观可见；高级条件规则和实验性能力按层级展开。

## 1. 产品目标、范围与术语

### 1.1 产品目标

**G1：** 在正常模式中提供流畅、可靠、可随时存档的标准 2048。  
**G2：** 在自定义模式中使玩家能够通过参数、预设和规则编辑器构造不同玩法。  
**G3：** 让整局对局成为可浏览、回放、比较和分叉探索的历史结构。  
**G4：** 允许玩家拥有自己的全部数据，并以明确的格式导出、导入和分享。  
**G5：** 在高自由度下保证可解释、可恢复、可测试与可扩展。

### 1.2 暂不承诺的范围

- 首版不要求在线多人联机、账号系统或云端排行榜。
- 首版不要求让第三方脚本拥有任意本地文件或网络权限。
- 首版不要求自动穷举全部 2048 可能局面；自动搜索与 AI 分析属于【后期】。
- 首版不要求无限内存、无限画布渲染或真正无限大的棋盘。

### 1.3 核心术语

| 术语 | 定义 |
|---|---|
| 规则集（Rule Set） | 控制一局游戏的参数、合并与事件规则，带版本和唯一标识 |
| 完整状态（Game State） | 足以恢复一局游戏的棋盘及全部运行时信息 |
| 操作（Action） | 玩家移动、施放技能、编辑局面等一次有语义的行为 |
| 历史节点（Node） | 某次已提交状态变化之后的可恢复历史位置 |
| 分支（Branch） | 从同一祖先节点开始发展的一条独立操作路径 |
| 检查点（Checkpoint） | 用户明确命名、收藏或备注的历史节点 |
| 快照（Snapshot） | 对完整状态的存储表示；不等于每个节点都存一份全量复制 |
| 探索分支（Exploration Branch） | 从历史节点重开、编辑局面或改变随机结果形成的分支 |
| 项目（Project） | 规则、元数据、全部分支、状态、资源及统计的可导出集合 |

## 2. 游戏模式与成绩边界

### 2.1 正常模式【确定 + 建议默认】

- **固定经典规则：** 默认 4×4；开局生成两个数字；每次有效移动后生成一个数字；数字 2/4 的生成概率默认 90%/10%；相同数值合并一次；上下左右操作；无可用移动时常规结束。
- **玩家仍然可以**随时自动/手动保存、查看时间树、导出整个项目、选择历史节点并再次行动。
- **建议默认：** 当玩家从旧节点重新行动、手动改动状态或重抽随机数时，生成带标记的“探索分支”；不与未经探索操作的单线成绩混排。
- **建议默认：** 纯查看与回放旧状态不会改变原对局状态，也不会把成绩标记为探索。

### 2.2 自定义模式【确定】

- 所有核心模块开放参数；可从预设、空白方案或已有方案副本创建。
- 任一配置需可命名、复制、比较、保存、导入与导出。
- 既支持无需编程的常规参数，也逐步加入“触发—条件—动作”的图形化规则编辑器。
- **建议默认：** 配置的发布版本与草稿版本分开；对正在进行的对局改变规则时建立新节点和规则版本引用。

### 2.3 成绩与标签【建议默认】

- 分别统计“正常模式·单线成绩”“正常模式·历史探索成绩”“自定义模式成绩”。
- 节点与分支记录是否使用编辑、重新随机、实验性规则、自动模拟等标签。
- 自定义模式的不同规则集默认不进入统一公平排行榜；可按同一规则集标识与版本做横向比较。

## 3. 自定义规则目录

> 下表给出规则空间，不代表每项必须在第一个可运行版本出现。原则是先定义可扩展的数据模型，再分批开放界面与行为。

| 模块 | 基础配置 | 高级/实验配置 | 初步优先级 |
|---|---|---|---|
| 棋盘 | 行、列、初始布局、可用格 | 障碍、冻结、传送、区域、动态扩缩 | P0 / P1 |
| 数字 | 初始数列、允许数值、目标数 | 数列生成器、特殊数字、任意精度 | P0 / P1 |
| 生成 | 数值权重、生成个数、生成时机 | 区域概率、阶段性概率、生成条件 | P0 / P1 |
| 移动 | 四方向、有效移动规则 | 单格、斜向、穿越边界、方向限制 | P0 / P2 |
| 合并 | 相同合并、得分规则 | 映射合并、相邻序列、多格、连锁 | P0 / P1 |
| 技能 | 开关、次数（含无限）、目标 | 冷却、恢复、成本、技能效果编辑 | P0 / P1 |
| 事件 | 开启/关闭预置事件 | 触发器、条件、动作链、优先级 | P1 / P2 |
| 胜负/计分 | 目标数字、失败规则、分数 | 多目标、组合条件、阶段目标 | P0 / P1 |
| 系统/展示 | 动画、操作、主题、提示 | 回放、随机种子、调试、性能预算 | P0 / P1 |

### 3.1 棋盘模块

**基础：** 行数与列数独立设置；支持非正方形；设置开局初始数字数量、初始具体布局和随机空位生成。  
**高级：** 格子层区分普通、禁用、阻挡、冻结、传送、增益；区域可以命名并用于生成/事件筛选。  
**设计约束：** “禁用格”不参与路径计算；“阻挡格”仍占据棋盘结构；格子效果是格子属性，不等同于数字块携带的效果。  
**【建议默认】** 配置编辑界面提供鼠标拖拽/触屏涂抹、矩形框选、批量清空、对称填充和撤销编辑。

### 3.2 数字模块

**基础：** 允许出现的数值集合、初始数字集合、可以自然生成的数值集合独立配置。  
**高级：** 2 的幂、3 的幂、斐波那契、等差、玩家定义列表；特殊数字可以携带锁定、不可合并、炸弹等状态。  
**技术建议：** 把空格与数字 0 明确区分；数值应具有可序列化的精确表示。首版以非负整数及明确的数值上限策略为宜；超大整数、负数、分数放在后期评估。

### 3.3 生成模块

**基础：** 每次生成 N 个数字，N 可以为 0；按权重或百分比选择数字；每种数字有独立权重；开局生成与回合生成规则分开。  
**高级：** 指定区域/格子生成、依步数或分数改变权重、随机生成数量区间、限定先后顺序、特殊生成事件。  
**空间不足策略：** 只生成至填满、跳过本次生成、转化为事件；须明确配置。  
**校验：** 全部权重为 0 且该阶段要求选择数字时属于错误；一局完全不生成新数字属于可被允许的特殊玩法。

### 3.4 移动模块

**基础：** 上下左右；有效移动才推动常规回合；可设置无效移动是否触发回合。  
**高级：** 单格移动、对角移动、限定方向、边界连接、旋转棋盘、复杂障碍移动。  
**技术限制：** 穿越边界不能允许数字永不停下；冲突位置、移动排序与优先级必须由规则显式规定。

### 3.5 合并模块

**基础：** 两个同值数字合为两倍值；每个新形成的数字在同一有效移动内不能再次合并。  
**高级：** 求和、数列邻接、指定映射（A+B→C）、多数字合并、链式合并、合并副作用和次数限制。  
**优先级建议：** 规则按明确的“优先级 → 规则 ID”排序；同一时刻只有一项主合并规则取得控制权，其余可以作为后续事件处理。  
**技术限制：** 对循环映射、链式合并设定单次操作执行预算，并在结果中保留中止原因。

### 3.6 技能模块

**首批技能建议：** 撤销、删除单格、交换两格、升级、降级、随机重排、生成指定数字、清空行/列、旋转棋盘。  
**每个技能独立拥有：** 是否启用、初始次数、剩余次数、最大储存次数、是否无限、冷却、恢复条件、消耗回合、可选目标、失败后是否允许使用。  
**重要区别：** “撤销技能”是规则内会消耗技能次数的一种游戏行为；“时间树导航/回到旧节点”是项目级历史操作，不消耗该技能，但重新出手会建立探索分支及成绩标签。  
**【待决策】** 是否允许技能本身创造多个子事件，并由图形化编辑器自定义效果。

### 3.7 特殊格子、特殊数字与事件

- **格子层：** 障碍、增益、传送、冻结等固定位置效果。
- **数字层：** 锁定、护盾、定时炸弹等随数字移动的效果。
- **事件层：** 按步数、分数、合并次数、某个数字出现、移动方向或定时器触发的效果。
- **规则编辑器建议：** 每条规则包含“触发时机 → 可选条件 → 动作序列 → 优先级 → 执行次数/冷却”。
- **示例：** 当最大数字首次达到 512 且剩余空格少于 4 时，随机删除一个非最大数字；一局最多触发 3 次。
- **安全边界：** 导入第三方规则配置时不执行任意宿主脚本，先实现受控动作集合与受限表达式。

### 3.8 胜负、回合与计分

- **胜利条件：** 达到目标数字、目标分数、指定回合完成目标、清除指定数字或多个条件组合；可设置获胜后继续。
- **失败条件：** 无有效移动、规定回合结束、倒计时归零、条件规则判定失败；需检查已启用的可挽救技能。
- **计分：** 经典合并加分、按合并次数加分、按数值权重加分及自定义公式。
- **无尽模式：** 可以不设胜利或失败条件，但界面仍显示统计和历史。
- **计时：** 要区分逻辑回合时间、实际游玩时长与实时倒计时；实时事件应被显式记录，以供回放。

## 4. 规则引擎与结算规范

### 4.1 单步的建议结算流水线【建议默认】

1. 接收并验证玩家操作（方向、技能或编辑动作）。
2. 捕获操作前状态标识、规则版本、随机数状态。
3. 根据移动规则计算位移及初始冲突解决。
4. 依据合并规则计算合并、分数和相关效果。
5. 执行有界事件链：技能副作用、格子效果、合并触发器等。
6. 按生成策略产生新数字，并记录实际抽取结果。
7. 更新回合、冷却、计数器、目标及胜负状态。
8. 对结果执行完整性检查；成功则原子提交历史节点并触发自动保存。
9. 界面根据已提交的状态变化播放动画；动画失败不能影响已提交结果。

实际允许在不同阶段挂载钩子，但必须定义钩子的先后顺序和单步最大执行预算。

### 4.2 不可违反的引擎不变量

- **相同输入确定结果：** 规则集版本、完整状态、玩家操作和随机流一致时，最终状态一致。
- **单次操作原子性：** 要么全部状态变化与历史节点写入成功，要么回滚，不留下半步状态。
- **无幽灵状态：** 回合数、技能次数、事件计数器等不能只存在于界面变量中。
- **错误可解释：** 无效配置、触发冲突、预算耗尽、恢复失败必须有可读诊断信息。
- **版本可追踪：** 每个节点可定位当时使用的规则版本与引擎兼容信息。

## 5. 完整状态模型与时间树

### 5.1 完整状态需要覆盖的内容【确定 + 建议默认】

| 状态域 | 内容 |
|---|---|
| 棋盘状态 | 布局、格子属性、数字值、数字块特殊属性 |
| 规则引用 | 当前规则集 ID、版本、扩展能力清单 |
| 玩家进度 | 分数、累计合并、回合、目标进度 |
| 技能状态 | 余量、冷却、恢复和使用统计 |
| 随机状态 | 种子、算法标识、内部状态/已抽结果 |
| 事件状态 | 待触发队列、计数器、临时效果、冷却 |
| 计时状态 | 累计用时、运行/暂停、计时模式、相关事件 |
| 结局状态 | 正在进行、获胜、失败、可否继续 |
| 自定义扩展 | 经声明的规则变量及其值 |

### 5.2 历史节点关系【确定】

- 每个项目有一个或多个独立对局根节点；单局的历史为**有根树**。
- 除根节点外，每个节点有且只有一个父节点；相同棋盘状态出现在不同路径，也不自动合并节点。
- 节点记录：唯一 ID、父 ID、操作摘要、创建时间、序列号、规则版本、状态校验摘要、快照/事件引用、可选备注与标签。
- 任何旧节点都可查看、恢复并再次行动；新动作接在该节点之下，不覆盖原有子节点。
- 收藏、命名、添加标签和归档分支默认不改变游戏数值状态；这些属于项目元数据操作。

### 5.3 时间树与“撤销技能”的区别【建议默认】

| 行为 | 历史导航 | 游戏内撤销技能 |
|---|---|---|
| 用途 | 查看、比较、探索不同路径 | 按规则付费/限次改动对局 |
| 消耗技能次数 | 否 | 是，除非配置为无限 |
| 是否创建新节点 | 仅查看不创建；继续行动才创建 | 视为一次有效技能操作并记录 |
| 正常模式成绩 | 从旧节点出手后记为探索路径 | 经典正常规则下默认不存在该技能 |

### 5.4 时间树可视化【确定 + 建议默认】

- 使用可缩放、可平移的树形画布，点击节点可见棋盘缩略图与完整状态摘要。
- 支持自动布局、折叠/展开分支、搜索节点、收藏、标签、筛选操作类型和小地图。
- 提供**树视图**与**单分支时间轴**；时间轴可按步回放，也可以展开一次操作内部的移动、合并、生成细节。
- 节点详情至少显示：分数、步数、最大数字、技能状态、随机信息摘要、规则版本、父节点及分支路径。
- 任意两节点可比较：格子变化、分数变化、操作数、技能消耗、规则差异；不同棋盘尺寸时显示映射/未匹配区域。
- 大树必须采用按需加载、视口渲染、分支聚合，避免一次绘制全部节点。

### 5.5 恢复、编辑与版本切换

- **恢复：** 从选定节点获得当时的完整状态；只查看不改变当前活跃分支。
- **从此继续：** 将选定节点设为新操作的父节点，保留已有分支。
- **编辑局面：** 创建“编辑动作”子节点，记录位置和旧/新值，不直接覆写原节点。
- **修改规则：** 派生新规则版本，在新子节点上生效；如棋盘尺寸变化，明确旧格子如何映射、溢出的格子如何处理。
- **删除/归档：** 首版优先可撤销的“归档”而非不可恢复物理删除；导出时可选是否包含归档分支。

### 5.6 快照与增量记录【建议默认】

采用“**操作事件记录 + 定期全量快照 + 状态校验摘要**”的组合：保留每次可重放操作和必要的已实现随机结果；按历史深度或数据量创建快照；恢复时从最近快照重建，再校验目标状态。

快照间隔先作为可调实现参数，待压力测试决定；不能预先保证所有规模都能无限量常驻内存。

## 6. 随机性、时间和可重放性

### 6.1 随机策略【建议默认】

| 策略 | 说明 | 历史要求 |
|---|---|---|
| 严格复现 | 同一历史节点执行同一操作，得到相同随机结果 | 固定生成器版本，保存随机状态及结果 |
| 重新随机 | 从相同局面重新抽取一次 | 新子分支携带新随机种子/结果 |
| 指定种子 | 用户给定种子以便分享挑战 | 记录种子与算法版本 |
| 手动指定 | 用户选生成值和位置 | 标记为实验/编辑性质的生成 |

### 6.2 计时与异步事件边界

- **回合触发事件**易于复现，建议优先实现。
- **真实时间倒计时**受暂停、浏览器挂起、系统睡眠影响；恢复时不得凭空推断旧计时结果。
- 建议在历史中记录计时事件及其发生逻辑时间；用户选择“回放历史”不触发新的现实定时器。
- 【待决策】计时对局恢复后采取“暂停等待用户继续”还是“按照现实经过时间结算”；建议默认前者。

## 7. 规则编辑器与冲突校验

### 7.1 逐层开放能力【确定方向，建议实现】

1. **基础面板：** 输入数值、滑杆、概率编辑器、技能开关、棋盘尺寸。
2. **高级编辑：** 区域、分阶段概率、合并映射、技能冷却和目标组合。
3. **图形化规则：** “触发 → 条件 → 动作 → 限制”组件化编排。
4. **实验表达式：** 有类型、无任意文件/网络权限的受限表达式或隔离环境【后期】。

### 7.2 校验等级

| 等级 | 示例 | 产品行为 |
|---|---|---|
| 错误（阻止启动） | 必须抽数字但权重全为零、规则解析失败、必然死循环 | 指向问题参数并给出修复建议 |
| 警告（允许启动） | 没有新数字、胜利目标似乎不可达、棋盘很大 | 明示后继续 |
| 提示（可忽略） | 与默认值差异大、已有未使用的技能配置 | 信息提示，不阻断 |

### 7.3 冲突处理与预算

- 同一阶段多个规则竞争同一变化时，依据**显式优先级、稳定次序、冲突策略**处理。
- 每条规则定义触发上限；每个操作定义最大事件数量/链深度，超过预算则有可诊断的中止方式。
- 对“规则 A 引发 B，B 又引发 A”应可静态预警，但最终仍以运行时预算保证终止。
- 不推荐首版开放直接执行用户输入的任意 JavaScript 或本机脚本。

## 8. 设置中心与游戏界面

### 8.1 导航结构【建议默认】

- **首页：** 继续游戏｜正常模式｜自定义模式｜对局项目库｜设置与帮助。
- **自定义入口：** 新建配置｜使用预设｜复制已有配置｜导入配置。
- **配置编辑器：** 左侧九类导航，中部参数，右侧棋盘实时预览，底部固定“校验 / 保存 / 开始”。
- **游戏中：** 棋盘主视图、分数/目标、技能工具栏、保存/导出、时间树入口。
- **时间树：** 中央树画布；侧面节点详情；搜索、筛选、双节点对比及时间轴回放。

### 8.2 减少设置复杂度

- 每个模块区分**基础 / 高级 / 实验性**选项。
- 开关关闭时隐藏无效子参数；复杂规则以折叠卡片呈现。
- 显示“已改动参数”与默认值的差异，可一键恢复某项/某类默认值。
- 支持配置搜索、参数释义、冲突即时校验、未保存变更提示。
- **实时试玩**使用独立沙盒副本，不写入正式对局历史；可以主动将试玩状态“保存为开局”。

### 8.3 PC 与移动端适配

- PC：三栏编辑器，时间树支持滚轮缩放、拖拽平移、快捷键和悬浮信息。
- 手机：分类抽屉+单列参数页；棋盘预览可以切换全屏；时间树采用触控缩放和节点详情底部抽屉。
- 核心操作需考虑键盘与触屏可达性、色盲区分与动画关闭选项。

## 9. 保存、导出、导入与数据所有权

### 9.1 保存范围【确定】

- **自动保存：** 每次状态提交后保存已提交节点与项目头信息；异常中断后尽可能恢复最近的已完成操作。
- **手动保存：** 随时创建带名称/备注的检查点；在暂停、胜利或失败界面也可使用。
- **随时导出：** 当前可恢复节点、选定分支、整个历史树或包含多个对局的项目库备份（项目库备份为【建议扩展】）。
- **设置导出：** 可仅导出规则，不包含任何对局记录。

### 9.2 推荐格式【建议默认】

| 导出类型 | 建议文件 | 主要内容 |
|---|---|---|
| 规则配置 | `.json` | 规则版本、参数、校验元数据 |
| 单节点状态 | `.json` / `.2048state` | 状态、必要规则引用或嵌入规则 |
| 单分支历史 | `.2048lab` | 路径节点、事件、快照、规则 |
| 完整项目 | `.2048lab` | 多分支历史、规则版本、标签、资源、统计 |
| 可视化分享 | `.svg` / `.png`【后期】 | 只用于展示，不承诺可恢复 |

`.2048lab` 为自定义扩展名，建议使用带清单、版本、校验摘要的压缩容器；导入时校验结构并采取防压缩炸弹、防路径穿越和大小限制措施。文件格式应由公开说明文档描述，而非依赖内部私有状态。

### 9.3 备份完整性与兼容

- 导入前只预览元数据，不主动执行任何携带脚本或外部资源。
- 记录数据格式版本、规则引擎版本、生成器版本；提供可迁移升级路径，无法迁移时只读打开或说明原因。
- 支持导出完整校验信息；恢复过程中校验节点状态，发现损坏时尽量定位并恢复未损坏部分。
- 隐私建议：默认本地优先，不要求登录即可保存或导出；未来云同步应为可选功能。

## 10. 非功能性要求与风险

| 领域 | 设计要求 | 验证方式 |
|---|---|---|
| 正确性 | 经典合并、分数、失败判定与边界规则正确 | 单元与性质测试 |
| 可回放 | 同状态同规则同随机输入结果一致 | 重播与状态校验 |
| 历史可靠性 | 分叉不覆盖旧分支，崩溃后恢复最后已提交节点 | 故障注入与导入测试 |
| 大规模数据 | 支持大树按需加载、节点虚拟渲染、可控快照间隔 | 1 万/10 万节点压力测试 |
| 极端棋盘 | 棋盘尺寸、内存使用与操作执行预算可配置并提示 | 不同规模性能测试 |
| 安全性 | 第三方配置不能直接执行危险代码；导入防恶意压缩包 | 输入模糊测试和安全检查 |
| 可访问性 | 键盘、触屏、足够对比度、减弱动画 | 桌面及移动端验收 |
| 可移植性 | 核心引擎不依赖界面框架 | 在独立测试环境中运行规则测试 |

### 10.1 关于“无限自由”的明确界限

**产品上不人为封死**棋盘、节点数或自定义规则的潜力；**技术上不能承诺无限内存与算力**。建议定义可调整的资源预算：单次操作事件数量、快照缓存量、历史画布一次渲染节点数、单项目导入体积等。预算超出时优先优雅降级，而不是程序崩溃。

### 10.2 建议的平台策略【待决策】

建议先开发可离线运行的 Web 版本，把规则、状态、历史存储与界面解耦；之后视需求打包桌面端和移动端。但**最终首发平台尚未决定**，不在本文件中强制指定技术栈。

## 11. 分阶段开发里程碑

| 里程碑 | 必须交付的范围 | 验收门槛 |
|---|---|---|
| M0：规格冻结 | 确认核心语义、节点结构、存档范围、正常模式成绩政策 | 无互相矛盾的关键规则 |
| M1：经典核心 | 标准 2048、状态引擎、原子操作、自动保存、基础树节点 | 可正常玩，任意已存节点可恢复 |
| M2：历史树与导出 | 分支保存、节点跳转、检查点、项目导入导出、基本对比 | 原分支不丢失，导出导入前后可回放 |
| M3：基础沙盒 | 行列、数字概率、生成数量、胜负条件、初批技能 | 配置修改生效，异常配置有提示 |
| M4：高级沙盒 | 棋盘编辑、合并映射、动态概率、基本事件规则 | 规则可复现，冲突可诊断 |
| M5：完整交互 | 图形化规则编辑、树画布优化、回放、统计、移动端适配 | 常见任务无需查看原始数据文件 |
| M6：稳定发布 | 导入安全、兼容迁移、性能测试、示例预设、帮助文档 | 关键验收场景全部通过 |

**优先级定义：** P0＝稳定核心所必需；P1＝完整沙盒主要能力；P2＝实验性扩展。里程碑并非强制对外版本号。

## 12. 核心验收场景

### 12.1 正常模式与计分

1. 新局为 4×4；开局两个数字；有效移动才按经典规则生成数字。
2. 同一格在一次标准移动中不能重复合并；得分与经典规则一致。
3. 无法移动时判定结束，但仍可保存、导出和查看树。
4. 回看旧节点但不产生操作时，单线成绩标签不变。

### 12.2 时间树与恢复

5. 连续操作产生 S0→S1→S2；从 S1 继续产生 S3 后，S2 保留且可恢复。
6. 历史树中的每个已提交节点都能还原当时棋盘、技能、计数器和随机状态。
7. 对旧节点修改格子后生成带编辑标签的新分支，原节点不变。
8. 纯浏览节点与实际从节点继续行动的行为、状态和成绩标签可明确区分。
9. 删除/归档分支不意外连带删除仍被其他节点引用的数据。
10. 比较两节点可正确识别棋盘、分数、技能和规则差异。

### 12.3 随机性与沙盒

11. 固定状态、规则和随机种子回放生成相同结果。
12. 选择重新随机会产生新分支，且其具体结果可再次回放。
13. 生成数量为零的有效自定义配置可以运行。
14. 权重全为零而又必须抽样时，系统提示配置错误，禁止开始。
15. 同时启用多种合并规则时，优先级计算有确定结果。
16. 复杂事件循环被预算中止并产生诊断信息，不冻结整个应用。
17. 撤销技能余量和时间树导航互不混淆。

### 12.4 存档、导出与性能

18. 任意有效操作之后异常退出，重新打开可恢复最近一次成功提交的状态。
19. 完整项目导出再导入后，节点数、父子关系、规则版本和校验摘要一致。
20. 一份规则配置可以独立导出、导入并创建新局。
21. 超大历史树可通过折叠、分段载入和视口渲染浏览，不要求全部节点同屏。
22. 非法文件、路径异常和超限压缩文件应被安全拒绝，不破坏已有存档。

## 14. 推荐的下一步工作

**先审阅并确认 D01–D06 六项基础决策。** 它们直接影响历史树的含义、存档范围、用户体验和开发平台；其余可分阶段继续讨论。

随后制作三份相互对应的下一阶段材料：

1. **规则参数字典**：逐项列出字段、类型、默认值、合法范围、冲突校验与界面位置。
2. **状态/历史数据契约**：明确完整状态、操作事件、历史节点、规则版本和项目文件之间的关系。
3. **主要页面线框稿**：首页、游戏页、自定义设置页、时间树、节点对比与导出页。

以上完成后再进入工程选型和编码，能够最大程度减少因高自由度与分支历史而引起的返工。

---

**文档结论：** 2048 Sandbox 不是“带很多开关的 2048”，而是一套可配置、可复现、可分叉、可分析、可导出的数字游戏实验平台。其最重要的底层投资应是稳定的状态引擎、确定性的规则结算，以及完整可恢复的历史树。
