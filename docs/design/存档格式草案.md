# 2048 Sandbox 存档格式草案

**版本：** 格式草案 v0.1，内部 `formatVersion=1`  
**日期：** 2026 年 10 月 14 日  
**状态：** 封装、阈值与迁移方案为建议；完整历史保存【D05】、节点不合并【D08】、默认压缩与快照去重【D12】已经确认。

**M2 实现说明：** 本文保留 M0 原始草案。当前可导入导出的格式、实际边界与迁移范围以 [存档格式 v1](存档格式_v1.md)为准，测试结果见 [M2 验收记录](../planning/M2_验收记录.md)。

## 1 文件与范围

| 导出内容 | 扩展名 | 必须覆盖的内容 |
|---|---|---|
| 规则配置 | `.json` | 完整规则版本、能力清单、definitionHash |
| 单节点 | `.2048state` | 完整状态、规则、来源元数据、撤销所需的依赖状态 |
| 单分支 | `.2048lab` | 根到选定节点的路径，以及路径外的必要恢复依赖 |
| 完整项目 | `.2048lab` | 全部对局根、历史、规则、检查点、归档标记、资源和项目设置 |
| 项目库备份 | `.2048backup` | 库级清单与多个独立项目，覆盖完整引用闭包【D05】 |

建议 `.2048lab` 与 `.2048backup` 使用 ZIP 容器，默认 DEFLATE 无损压缩；容器清单保持可直接识别。M0 的 `contract-example.json` 是便于审阅的展开样例，不是已经发布的存档实现。

## 2 项目容器结构

```text
manifest.json
project.json
rules/<rule-id>/<version>.json
nodes/<match-id>/index.json
nodes/<match-id>/part-000001.jsonl
states/<sha256-hex>.json
deltas/<sha256-hex>.json
assets/<sha256-hex>.<ext>
```

manifest 包含 formatVersion、exportKind、exportedAt、projectId、rootNodeIds、selectedNodeIds、requiredCapabilities、entryCount、entries。每个 entries 项记录相对路径、逻辑类型、未压缩字节数和 SHA-256 摘要；摘要覆盖条目解压后的原始字节，不能用 ZIP 的 CRC 替代。

清单不包含自己的摘要，避免自引用；manifest 的结构、条目表和引用在导入时共同校验。完整项目可导出所有状态，也可导出检查点与增量；任何选择都必须能够恢复每个包含的节点。

项目库外层清单记录各 projectId、项目条目路径与摘要；各项目独立命名空间，不因节点 ID 相同而混合。外层不嵌套 ZIP，建议使用 `projects/<project-id>/...`，以便统一限制解压总量。

## 3 完整状态与去重

完整状态规范化字节的摘要作为 states 条目的地址。不同节点引用相同完整状态时共享条目，节点记录、父子关系、动作与元数据各自保留【D08、D12】。

棋盘相同而技能余量、随机流、规则引用、撤销栈或计数不同，不能按完整状态去重。压缩只是存储表示，不参与游戏规则；改变压缩等级不能改变状态摘要和节点语义。

建议 M1 全量状态先行，M2 再加入增量。增量需要自己的格式版本、baseStateHash、resultStateHash、变化列表；不允许只能依赖最新版引擎才能理解的隐式 UI 状态。

## 4 导出闭包

1. 确定导出范围：节点、路径、全项目或项目库。
2. 加入必要父链、规则版本、快照、增量基础与资源。
3. 加入 undoStack 和 undoTargetId 所引用的恢复目标及依赖；不因目标位于被折叠或归档分支而遗漏。
4. 固定一个已成功提交的项目 revision，导出该一致视图，避免一边操作一边混入新节点。
5. 计算条目摘要与清单，压缩并写入新文件；失败不改变本地项目。

“不含归档分支”的局部导出仍需保留依赖闭包。界面显示导出节点数、是否完整项目、是否含归档、是否附带恢复依赖；不得把裁剪后的分享文件显示为完整备份。

## 5 导入流程

```mermaid
flowchart LR
  A[选择文件] --> B[检查容器和清单]
  B --> C[预览范围与能力]
  C --> D[流式解压并限制资源]
  D --> E[验证摘要 结构 引用与树]
  E --> F[临时导入区]
  F --> G[事务写入新项目]
  G --> H[打开节点 计时暂停]
```

导入默认创建独立副本，保留来源 ID 到本地 ID 的映射。遇到相同项目 ID 不覆盖现有项目；用户显式选择合并时才进入后续的合并方案。M2 首版先支持导入副本。

能力清单不满足时，在预览中列出具体能力；可完整显示已存状态时允许只读打开，禁止继续执行不支持的规则。对不能安全解析的未知格式拒绝打开。只读不是跳过校验的借口。

## 6 初始导入边界

| 资源 | 建议默认 | 超限行为 |
|---|---|---|
| 解压后总大小 | 256 MiB | 中止本次导入，已保存项目不变 |
| 条目数 | 100000 | 中止，不预先创建海量数据库记录 |
| 单条目大小 | 32 MiB | 拒绝该文件，提示拆分状态或分段导出 |
| 解压压缩比 | 200 | 按实际流式输出判断，不能只信 ZIP 头 |
| 相对路径长度 | 240 个 ASCII 字符 | 拒绝异常条目 |
| 节点关系 | 同局单父、无环、深度正确 | 返回具体节点与问题 |

这些值是待压力测试调整的策略，不是承诺的设备能力。检查绝对路径、盘符、`..`、反斜杠混淆、NUL、重复规范化路径、符号链接、嵌套容器和加密条目。资源不自动发起网络请求，规则不携带可执行宿主脚本。

## 7 版本与迁移

- 清单格式、状态格式、规则格式、随机算法和增量格式分别带版本，不能用应用版本号代替。
- 迁移生成新副本，保留原文件；每步记录输入版本、输出版本和诊断。
- 没有迁移器时拒绝执行或只读恢复已支持的完整快照，不用猜测填充缺失技能、分数或随机状态。
- 摘要不匹配的状态标记损坏；只允许显式选择导入已验证的独立部分，并说明不完整范围。
- 不主动物理删除旧分支；资源垃圾回收先计算完整引用集合，再执行独立维护事务。

## 8 M2 验收

完整导出再导入后，根节点、节点数、父子关系、分数、技能、随机输入、规则版本和状态摘要一致。项目库多个项目均可恢复。新项目实际计时暂停【D10】。

还需验证断电或标签页关闭、配额不足、条目损坏、重复路径、未知能力、旧版本、部分导出依赖以及归档恢复。只通过 JSON Schema 不代表 ZIP 导入、存储事务或游戏回放已经通过。

相关结构见 [状态与历史数据契约](状态与历史数据契约.md)，实现取舍见 [工程选型](../planning/工程选型.md)。
