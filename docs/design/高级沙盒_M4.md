# 2048 Sandbox 高级沙盒 M4

**日期：** 2026 年 10 月 14 日  
**应用版本：** 0.6.0  
**范围：** 棋盘草稿编辑、对局中规则版本化修改、映射/数列/连锁合并、位置与阶段生成、受控事件。

## 1 编辑棋盘

在游戏左侧点击“编辑本节点棋盘”。设置画笔数字后点选格子，或勾选“清空画笔”删除数字；“清空棋盘草稿”一次清空全部格子。数字 0 占格，空格为 null。画笔使用精确非负整数字符串，遵守当前位数预算和允许数字列表。

草稿提供最多 50 个本地版本，可撤销、重做、还原或关闭取消。这些操作不修改存档、不计游戏操作。只有“提交棋盘编辑”才创建所选节点的新子节点；未改动的草稿不能提交。

提交成功增加一次有效操作，不推进世界回合或计费回合、不自动生成数字、不消费随机数。成绩、合并计数和当前技能账本保留，随后运行已配置的“编辑或发布规则后”事件并重新判断目标；事件可进一步改变棋盘、成绩或资源。原节点始终保留。

支持 editing-v1 的规则下，普通棋盘编辑进入技能撤销栈。固定经典规则和旧 M3 规则首次编辑时，同一笔保存同时派生自定义规则并写入编辑节点；此次形成规则版本边界，撤销栈清空。之后仍可免费从旧历史继续。

## 2 发布规则版本

点击“修改本节点规则”，在基础表单和“高级规则”中调整参数。底部预览展示尺寸、搬移/丢弃数量、涉及模块、当前成绩和技能余量变化。点击“发布规则新版本”后，新规则、候选状态、新子节点和活跃位置一起提交。

自定义规则沿用规则 ID，并使用本地同 ID 所有已保存版本的最大值 +1。这样从旧节点或导入副本修改也不会覆盖已存在的版本。固定经典规则派生新的自定义 ID。多页同时发布发生版本/项目冲突时整笔拒绝，可重新读取后再发布。

每个节点按自己状态中的 ruleRef 取规则；回看旧节点、旧节点继续、回放和文件导入均不使用最新规则重新解释旧棋盘。

规则发布增加一次有效操作，保持当前随机流，不推进世界回合和计费回合；清空技能撤销栈。新版本之后的操作建立新的栈，免费历史导航仍可跨越版本。初始布局、开局数量和开局分布只影响之后的新局，不会重新铺到当前棋盘。

## 3 尺寸与运行状态迁移

数字按左上角坐标对齐，不按旧数组索引直接复制。缩小棋盘有三种明确策略：

| 策略 | 行为 |
|---|---|
| 取消 | 存在溢出数字时禁止发布 |
| 搬移 | 按原索引升序放入新棋盘索引升序的空格；空间不足时整笔拒绝 |
| 丢弃 | 预览明确列出受影响数字，提交后丢弃；原数字留在旧节点 |

缩小后初始布局、事件格索引和位置权重仍需符合新尺寸。当前数字超过新位数预算时拒绝迁移；允许数字列表限制布局、生成、放置与编辑，不删除现有数字或限制合并/升级结果。

迁移保留当前成绩、合并次数、世界回合、有效操作账本、已用技能次数和随机流。有限次数最多保留到新最大储量；有限改无限变 null，无限改有限取新初始次数。冷却截到新冷却上限，恢复进度按新周期取余，关闭恢复则归零。启用新技能不额外赠送已存账本以外的次数。

仍存在的事件 ID 保留执行计数并截断冷却；新事件从 0 开始。仍声明的变量保留当前值，新变量取初值，删除变量移除运行值。目标定义变化时清空旧达成记录，再按当前世界重新判断；目标未变化时保持历史达成语义。

## 4 合并与数列

| 合并方式 | 行为 |
|---|---|
| 同值相加 | 相同值求和；经典规则保持每块每步最多合并一次 |
| 映射合并 | 定义左值、右值和结果；可区分滑动方向上靠目的端与远端的顺序 |
| 相邻数列 | 数列相邻两项合并为较高项的后一项；首项+首项得到第二项，末端没有后一项时不合并 |

映射按优先级降序、ruleOrder 显式顺序、ASCII ID 升序确定首个匹配项。界面设置优先级，规则文件也可携带 ruleOrder。未匹配时不合并，不回退到同值求和。每次合并按结果数字乘计分倍率加入节点成绩。

开启“允许新合并块继续连锁”后，结果可继续与已经排到目的端的数字合并。单块合并次数限制为 1–64，按参与数字的最大既有合并深度 +1 累计；整步合并也受 10000 次预算约束。关闭连锁时新块不再次合并。

例如 `[2,2,4,8,空]` 向左：默认得到 `[4,4,8,空,空]`，加 4 分；连锁上限 2 得到 `[8,8,空,空,空]`，加 12 分；上限 3 得到 `[16,空,空,空,空]`，加 28 分。

自定义数列也供升级/降级技能使用，分别取下一项/上一项；不在数列内或没有相应邻项时拒绝。数列顺序由输入决定，数字互不重复，至少两项。只选择技能数列不会自动改变合并方式。

## 5 位置权重与阶段生成

生成位置可选所有空格均匀，或指定格索引/权重。加权位置仅包含当前为空且权重为正的格子，未列出的格子不参与；没有候选时跳过生成，不偷偷回退到均匀。整批跳过策略以实际可用候选数量判断。开局也使用所选位置策略。

阶段包含优先级、条件、数字权重及可空生成数量。数量留空沿用基础数量；按优先级降序、ASCII ID 升序选择第一个满足条件的阶段，未命中时使用基础分布。阶段判断发生在本步生成前事件之后。

每个生成项先抽数字再抽位置，候选按格索引升序排列；唯一候选不消费随机数。零生成、没有合法空格和整批跳过均不消费随机数。既有经典抽取顺序保持不变。

## 6 触发、条件与动作

事件以表单组合受控选项，无需写脚本。条件支持精确数值比较、全部满足、任一满足和取反；比较源包含节点成绩、世界回合、有效操作数、累计合并次数、空格数、变量和指定事件累计执行次数。

| 触发 | 时点 |
|---|---|
| 移动后 / 技能后 | 基础效果与操作/回合账本结算后 |
| 合并后 | 上述阶段后按本步合并次数发出信号，读取当前结算状态 |
| 生成前 / 生成后 | 本步命中生成触发时；生成前事件之后选择阶段，生成后在该批结束时 |
| 回合后 | 本步推进规则回合时，生成阶段之后 |
| 编辑或发布规则后 | 棋盘编辑或规则发布完成迁移后，目标判断之前 |

开局不运行这些事件。默认同一规则在一步内最多触发一次；允许重复触发后仍受累计次数、冷却、条件和执行预算约束。“最多执行次数”是世界状态中的累计计数，不是每步次数；null 表示不限。事件冷却随推进的计费回合递减。

动作可放置/删除数字、增加成绩、设置/增加变量、补充技能次数及发出受控触发信号。有限技能次数不超过最大储量；事件直接放置可替换已有格子。变量为精确非负整数，变量名为 ASCII 标识符，禁止原型保留名。

同一触发按事件优先级降序、ASCII ID 升序执行，动作按数组顺序执行；动作发出的信号进入 FIFO，当前信号的规则处理完后再消费。条件总量最多 4096、嵌套最多 16，事件最多 64，每事件最多 64 个动作，待处理队列最多 1024。一步共享 10000 单位预算，入队、出队、规则执行和动作均计费。

预算耗尽、队列过长、计数或数字超出预算均整步回滚：不写棋盘、随机流、事件计数、资源和操作数。页面保留原状态并显示诊断；可以修改有问题的规则再继续。事件不是独立有效操作，不额外创建节点。

事件计数、冷却和变量属于世界状态；撤销会恢复它们，当前技能资源和随机流仍按 M3 语义继续。配置了“技能后”的事件会在恢复世界并扣除撤销成本后继续执行。

## 7 文件与边界

M4 沿用数据库 v3、核心 schemaVersion=1、容器 formatVersion=1。新增 editing-v1、advanced-v1、events-v1 能力，清单覆盖全部规则。规则变化与首次派生规则的棋盘编辑强制保存完整文件快照；普通编辑可使用增量，引用闭包包含所有实际 ruleRef。

旧 M1/M2/M3 状态和规则不被补写新字段，原有状态摘要保持不变。旧应用遇到新能力应拒绝执行；M4 导入仍校验摘要、所有节点的原规则回放和资源预算。示例见 [演示存档](../../examples/projects/README.md)。

计时、墙/保护格、非方形 90/270° 旋转、任意脚本与未知规则只读导入未开放。M5 继续完善图形编辑、树与统计交互，M6 再做发布稳定性和性能验收。本轮证据见 [M4 验收记录](../planning/M4_验收记录.md)。
