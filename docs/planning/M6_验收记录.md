# 2048 Sandbox M6 验收记录

**日期：** 2026 年 10 月 14 日  
**应用版本：** 0.8.0  
**结论：** 本地版的稳定性、规模性能、预设、帮助和可携带程序包已完成；174 项单元、41 条浏览器、8 项发布及 5 组规模检查通过。

## 1 交付

| 范围 | 行为与证据 |
|---|---|
| 提交读取 | 按复合主键读取本步依赖，长链提交不再扫描全项目；每次完整打开和保存后确认仍回放全部节点 |
| 批量校验 | 共享规则、快照只检查一次，按项目回放；未引用旧条目仍校验，重复规则、摘要错误或动作不一致拒绝 |
| 取消导入 | 每 64 项校验让出事件循环，取消信号贯穿解压后的摘要/还原、回放和副本准备；取消和换文件不写入、不显示旧结果 |
| 容器边界 | 清单选择位置必须包含项目实际活跃节点；继续拒绝格式/能力未知、引用缺失、解压超预算和回放不一致 |
| 可用预设 | 连锁合并、斐波那契、九技能练习、阶段与奖励；界面选择只填写草稿，创建才保存，导入 JSON 与界面同源 |
| 本地帮助 | 欢迎页和对局均可打开，离线可用；说明输入、历史、撤销、存储地址、备份、失败处理及未开放范围 |
| 程序包 | 原生 Node 本机 HTTP 服务、启动入口、版本标记、完整文件摘要、ZIP 校验和、第三方许可原文；不含个人数据和 node_modules |
| 发布验证 | 解压完整包后独立启动，实际手机离线试玩；摘要校验能发现被改写文件，同一输入重复打包摘要一致 |

不增加依赖；规则能力、Schema、数据库 v3 与存档容器 v1 继续沿用。游戏结算语义保持一致，回放工厂只复用已校验的私有规则副本，不省略每步状态/动作校验。v0.1、v0.2 原稿与既有演示材料保持不变。

[server.test.mjs](../../tests/release/server.test.mjs) 与 [package.test.mjs](../../tests/release/package.test.mjs) 检查 GET/HEAD、MIME、缓存更新、缺失资源、非法方法、Windows 路径和编码穿越、端口冲突、依赖独立启动、ZIP/文件摘要、实际构建一致、第三方许可、无个人数据及重复打包一致。Windows PowerShell 5 真实启动入口已验证：直接读取版本，系统默认 Node 较旧时自动选择符合 24.19+（24.x）的可用运行环境，无需经 `-e` 传递引号敏感的命令。

## 3 浏览器流程

[m6.spec.ts](../../tests/e2e/m6.spec.ts) 增加 5 条流程，使用隔离的 Chrome 上下文，生产资源通过正式的原生 HTTP 服务提供，不操作用户已有对局。

| 流程 | 核对 |
|---|---|
| 桌面离线预设与帮助 | 未开局可看帮助；选择预设不写库，四套预设逐一创建并完成首步；帮助开启时方向键不操作棋盘 |
| 手机离线预设与帮助 | 390×844 同样完成四套预设、保存与刷新恢复，页面无横溢 |
| 大文件取消与换文件 | 1,001 节点平衡树校验期间取消，再选连锁规则；只出现新文件预览，确认前数据库完全一致 |
| 长链真实恢复 | 1,001 节点界面导入，树视口 5 个节点；新增操作保存为第 1,001 步，刷新精确恢复；导出全部 1,002 节点，再恢复副本，两局共 2,004 节点且原局保持原值 |
| 解压版独立运行 | ZIP 与清单摘要一致，改写文件能被校验发现；解压包无需依赖安装，手机创建阶段奖励局，首步 14 分，断网重开后帮助与进度均可用 |

原有 M1–M5 流程继续检查：M1 数据库升级与 JSON 迁移、撤销和规则版本、异常退出、配额整步/整批回滚、幂等重试、多页冲突、离线新建/导入、等待保存后应用更新、历史与统计只读等。

## 5 使用与后续

[本地发布 ZIP](../../release/2048-sandbox-v0.8.0.zip) 附 SHA-256、32 个文件和 26 个第三方包的许可原文；[使用说明](../release/本地版使用说明.md) 已包含在包内。无需 pnpm、Vite 或安装项目依赖，运行时需要 Node.js 24.19+（24.x）；开发机启动入口可使用现有 Codex 运行环境。首次准备离线资源无需外网。

M0–M6 的已定本地范围在本轮收口，下一步可以实际试玩并按反馈修复；外部部署由具体发布需求决定。计时、保护格、非方形直角旋转、未知能力只读导入等仍需独立规格，不计入本轮完成。程序 ZIP 不含游戏数据，更新前应另外导出 `.2048backup`。
