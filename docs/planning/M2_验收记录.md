## 2 数据完整性

导入时重建并验证每份完整状态、父子树、规则和随机回放。副本映射项目 ID，保留原始节点 ID、父链、undoStack、分数、计数、随机输入/输出和状态摘要；数据库以项目 ID + 节点 ID 隔离历史，operationId 也按项目隔离。

源快照相同的复制节点仍是独立节点；不同项目的同状态可共享底层快照。检查点 ID 使用新本地 ID，关联节点与名称保留，归档标记保留。导入来源记录在项目元数据和批次表中。

导出通过一笔只读事务获取一致视图。解析、摘要、增量重建和回放检查不在写事务内执行。导入一次提交全部项目、节点、快照、规则、检查点、活跃设置和批次记录；失败不留下部分副本。

## 6 实现取舍与后续

- 历史树使用自有 SVG、迭代树布局与视口筛选，保留节点列表；本阶段无需 React Flow/Dagre。大规模应用恢复/导出性能仍需后续测量。
- 本地保存继续使用完整快照；可携带文件使用完整快照与增量。当前导出包含归档，未提供覆写或合并既有项目的导入模式。
- M2 执行经典规则。未知规则/能力明确拒绝写入，尚未提供未知规则的只读导入。
- 格式迁移只支持明确列出的 M1 JSON v1 和本地数据库升级；未知版本没有通用迁移或自动损坏修复。
- 当前普通 ZIP 的边界为压缩文件 64 MiB、展开 256 MiB、单项 32 MiB、50000 条目、压缩比 200；这些是拒绝策略，非设备性能承诺。
- 升级后旧应用页签需刷新；未承诺新旧代码长期并行使用同一数据库。
