## 2 设计必须贯穿的约束

1. **节点拥有成绩。** 状态恢复、节点详情、分支比较和导出都读取节点的分数；全局统计如需缓存，应能从节点推导。
2. **重抽与回放分开。** 新分支默认获取新的随机上下文；历史回放使用已记录的上下文和结果。复现模式要求相同节点、操作及随机输入得到相同结果。
3. **技能留下操作记录。** 撤销和其他成功技能都计入有效操作，创建新节点并自动保存；技能是否推进规则回合、触发生成，仍由技能与生成参数表达。
4. **节点不合并。** 相同完整状态可以共用底层快照数据，但历史节点 ID、父子关系、来源和操作记录必须独立。
5. **完整状态可恢复。** 棋盘、分数、技能、事件计数、随机状态、计时与规则版本都纳入契约；修改规则形成新版本及子节点。
6. **离线可用。** 第一阶段以本地保存和文件导入导出满足数据需求；首发采用离线 Web，云端能力不进入当前主线。

### 3.1 规则参数字典

已形成 [规则参数字典](../design/规则参数字典.md)，覆盖九个模块，并区分正常模式锁定值、自定义配置、项目设置与对局中版本化修改。

优先细化有效操作数与逻辑回合数的区别、技能成功和失败的判定、生成是否由技能触发、无可挽救技能时的失败判定，以及精确整数的范围和溢出处理。数字 0 与空格需要独立表示。

### 3.2 状态与历史数据契约

已形成 [状态与历史数据契约](../design/状态与历史数据契约.md)，描述以下实体及边界，并附 [契约样例](../../examples/contracts/README.md)：

- `RuleSetVersion`：不可变的规则版本和能力清单。
- `GameState`：完整游戏状态，包括节点成绩和全部运行时状态。
- `Action` 与 `ActionResult`：动作输入、合法性、结算结果、事件和诊断。
- `RandomContext`：算法版本、种子或内部状态、分支来源和实际抽取结果。
- `HistoryNode`：父节点、动作、规则引用、状态摘要和快照引用。
- `Project` 与项目库清单：对局根、活跃节点、检查点、标签、资源和备份范围。

优先用具体例子检查以下情形：

1. S0→S1→S2，从 S1 重新操作产生 S3；S2 与 S3 各自保有分数和随机记录。
2. 在 S2 使用撤销，创建 S2 的子节点并引用恢复目标；有效操作数增加，原路径保留。
3. 撤销恢复哪些字段、如何结算技能消耗和冷却、是否推进规则回合，必须明确，避免恢复时把本次消耗一并抹除。
4. 同一父节点同一动作：默认重抽可产生不同结果；复现模式可重现；两种结果都能稳定回放。
5. 两条路径形成相同棋盘但技能或随机状态不同，应识别为不同完整状态。
6. 对局中缩小棋盘、更换合并规则时，定义格子映射、溢出处理和规则版本引用。

### 3.3 页面线框和关键流程

已形成 [主要页面线框说明](../design/主要页面线框.md)与[交互线框](../design/页面线框.html)，按上述八条流程组织。交互线框使用预置数据；真实存档和引擎行为另行实现与验收。

节点预览应同时呈现分数、有效操作数、回合数和来源。纯预览不改变活跃对局；“从此继续”明确选中后续操作的父节点，实际行动时才写入新节点。

## 4 建议的工程模块

M1/M2 已按以下职责建立目录，具体模块与运行命令见根目录 README。

| 建议位置 | 职责 | 主要依赖 |
|---|---|---|
| `src/domain/` | 状态、动作、规则、节点等共享类型与契约 | 无界面依赖 |
| `src/engine/` | 移动、合并、技能、事件、胜负与原子结算 | domain、显式随机输入 |
| `src/random/` | 可序列化随机流、重抽与复现上下文 | domain |
| `src/history/` | 分叉、恢复、检查点、完整性验证与树布局 | domain、engine |
| `src/persistence/` | 本地事务、完整快照、去重、导入批次及数据库迁移 | domain、history |
| `src/files/` | ZIP、流式解压、增量、导出闭包、格式迁移与副本计划 | domain、history、persistence |
| `src/presets/` | 经典规则及示例自定义规则 | domain |
| `src/ui/` | 棋盘、设置、技能栏、时间树和页面流程 | 通过应用层调用引擎和存储 |
| `src/app/` | 协调输入、提交、持久化与界面状态 | 上述模块 |
| `tests/` | 规则、回放、恢复和导入导出的验证 | 独立于实际页面布局 |
| `public/` | 图标、静态资源和离线资源 | 构建方案确定后细化 |

规则引擎应能在无浏览器、无页面组件的环境运行。随机源、时钟和存储由外部提供，避免规则里读取不受记录的现实时间或随机数。[工程选型](工程选型.md)已提出 TypeScript + React + Vite、IndexedDB / Dexie 与 PWA 方案，并核对候选版本；实际依赖兼容性由 M1 安装构建验证。
