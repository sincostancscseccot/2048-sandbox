## 2 关键语义

统一纯结算函数接收完整状态、规则、动作、随机输入和恢复目标查询，返回完整候选。核心不访问数据库或隐藏随机源。经典 API 保持严格身份，原经典随机顺序、状态摘要和回放继续通过回归。

连续撤销验证了 S0→S1→S2→U1→U2：世界成绩 0→4→12→4→0，操作次数 0→1→2→3→4，默认撤销不推进计费回合，撤销余量 3→2→1。另验证恢复后成绩不足不能支付成本、其他技能已用次数不返还、冷却和恢复进度从当前账本继承。

导入副本只映射项目 ID，保留节点、撤销目标、完整资源与状态摘要。按实际 ruleRef 加载不可变规则，混合备份不再假设每局都使用经典规则；摘要、能力与全节点回放在写入前验证。

## 4 浏览器完整流程

[m3.spec.ts](../../tests/e2e/m3.spec.ts)增加 8 条流程；M1 的 7 条和 M2 的 5 条持续通过。使用隔离 Chrome 上下文和生产 PWA，未操作用户浏览器中的对局。

| 流程 | 证据 |
|---|---|
| 配置校验与取消 | 非法尺寸、全零必需权重、回合上限、技能恢复间隔可定位；保存库完全未变化 |
| 九种技能与选格 | 实际按钮/格子施放；0 成功放置；非法删除和选格期间键盘均不写数据 |
| 连续撤销与保存重开 | 原分支保留；资源与操作次数正确；刷新后完整库一致，树显示技能来源和实际格数 |
| 混合备份到空浏览器 | 经典与自定义两局恢复，全部状态摘要、规则、资源一致，源库保持原样 |
| 离线复制规则和继续 | 断网重开后可打开设置、复制 3×5 规则、创建新局并移动 |
| 实际 IndexedDB 配额故障 | 撤销保存两次失败均整体回滚；三次写入沿用同一节点 ID，恢复后只扣一次 |
| 手机大棋盘 | 390×844 配置窗口无横溢，创建按钮完整可见；3×10 原生触摸滚动不触发游戏操作，选格保存正确 |
| 规则 JSON | 导出真实自定义规则，导入预览不写，坏摘要/未知能力拒绝，确认后创建新局 |
| 重开与经典入口 | 沿用当前自定义规则并保留旧局，固定经典入口创建 4×4 正常对局 |
| 配置资源与回合上限 | 界面设置成本/冷却/恢复，达到上限后可撤销；按恢复后成绩扣费，刷新后资源一致 |

生产预缓存 16 项、约 629 KiB，包含设置、树与文件模块。无需在线游戏服务、外部字体或图片。
