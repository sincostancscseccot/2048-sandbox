# 2048 Sandbox v0.9.0 本地版

解压整个程序 ZIP 后，双击 **启动试玩.cmd**，保持终端窗口开启，在 Chrome 或 Edge 中打开 **http://127.0.0.1:4173/**。程序只监听本机，不需要账号，也不需要联网或安装项目依赖。运行环境为 Node.js 24.19 及以上的 24.x；开发机也可使用已有的 Codex Node 运行环境。

## 玩一局

- 经典：点击“开始经典对局”。使用方向键、WASD、方向按钮或在棋盘上滑动。
- 展开“我的对局”后键盘仍可移动当前棋盘。每次按下处理一步，长按不连走；保存中的方向输入不会滚动网页。输入框、弹窗和首页保留自身键盘行为。
- 自定义：打开“自定义新局”，展开“探索预设玩法”，选择连锁合并、斐波那契、技能练习场或阶段与奖励。选择只填写配置；点击“创建自定义对局”才保存新局。
- 每次成功操作自动保存，等状态显示“已自动保存”后再关闭窗口。技能、撤销、编辑也计入有效操作；默认无效移动不计步。
- 历史预览不会改变保存位置。“从此继续”后操作会保存新分支；默认重新抽取，也可选择复现随机结果。原有分支继续保留。
- 撤销恢复世界与成绩，消耗当前节点资源并保留当前随机流；规则版本变化建立新的撤销边界。
- 棋盘编辑在草稿中操作后显式提交；规则修改先预览迁移再发布新版本。统计页面显示所选节点的规则与路径数据。

页面右上角“帮助”包含详细说明，离线也能打开。

## 返回首页与删除对局

顶部“返回首页”或左上角品牌图标会返回欢迎页，已保存的棋盘、成绩、分支和检查点全部保留。点击“继续已保存的对局”或“我的对局”，再选记录，即可从保存节点继续。欢迎页的“开始经典对局”始终新建经典 4 × 4 对局。重新打开页面仍按原有机制恢复最后保存的对局。

“我的对局”每条记录右侧有“删除”。点击后先核对名称，再点击“确认删除”，删除这局的全部分支与检查点；无法撤销，其他对局和已有文件备份仍保留。删除当前对局后返回首页，删除最后一局后可重新开始。

保存尚未确认时，返回首页与删除会暂时禁用，请先重试保存或重新读取已保存进度。删除失败会保留原数据并允许重试；若另一页面刚保存了这局，需要关闭确认窗口，在列表中重新选择后再确认。删除可离线使用，不影响音效与外观偏好。

## 动画、音效与外观

“动效与声音”提供滑动动画、游戏音效和氛围光影三个独立开关，以及音量和试听。棋盘下方可快速切换动画与音效。偏好保存在当前浏览器、同一地址下，并同步到其他同源页签；这些设置不改变规则、成绩、历史或游戏备份。

操作保存成功后，方块滑到目标位置，再出现合并结果与新数字。音效包含移动、合并、撤销、技能、编辑、开局和胜负；历史回看、重新读取和检查点不重复播放成功音效，保存失败也不会提前播放。音效由浏览器生成，无需外网或额外下载，首次操作后可播放；切到后台会停止，关闭音效或音量归零会立即静音。

氛围开关控制纸色背景、棋盘柔光、方块质感及成绩变化提示；关闭动画后显示静态结果。系统开启“减少动态效果”时自动简化，密集棋盘也会简化动画以降低开销。

## 保管数据

游戏数据保存在**当前浏览器、当前站点地址**的 IndexedDB 中，程序文件夹里不保存个人对局。请固定使用 `http://127.0.0.1:4173/`。更换浏览器、端口、`localhost` 或其他地址会进入另一份存储。

定期点击“导出备份”，将 `.2048backup` 保存在自己选择的位置。恢复时打开“文件与恢复”，选文件，等待校验预览，再点击“导入副本”。恢复不会覆盖原对局；校验期间可以取消。支持正式容器 v1、规则 JSON 与 M1 JSON v1；未知格式或能力会明确拒绝。

**程序 ZIP 和游戏备份是两个不同的文件。** 程序更新前先导出游戏备份。清除站点数据、隐私浏览结束或设备损坏可能导致本地数据丢失。

## 离线与更新

启动本地服务并打开页面，等“离线资源已就绪”。完成缓存后，同一浏览器可断网重开、继续操作和导入备份。首次准备资源也无需外网，因为资源都在程序包中。

更新时关闭旧服务，解压新版到新文件夹，仍使用同一浏览器与 `127.0.0.1:4173` 打开。出现“新版本就绪”时先完成保存，再点击更新。不要清除站点数据。此流程保留浏览器中的对局；必要时通过已有备份恢复副本。

## 出现问题

- 保存未确认：棋盘显示最后确认状态。点击“重试本次保存”会确认同一笔操作，不重复抽签或扣费；需要放弃待确认操作时重新读取保存进度。
- 另一页面已更新：切回单个页面，重新读取保存进度后继续。
- 对局被另一页面删除：点击“重新读取已保存”回到首页，再选择记录或开始新局；已删除局不会被重新写入。
- 存储空间不足：本步事务回滚，先导出已保存数据，再处理浏览器空间并重试。
- 完整备份校验失败：应用会尝试导出原始恢复 JSON，保留它用于诊断。损坏数据不会被当作可正常恢复的数据导入。
- 端口占用：先关闭上一次启动的服务窗口，再启动；不要随意换端口寻找原有对局。
- 页面资源错误：先运行下方程序文件校验，重新完整解压后重试。Ctrl+C 可停止本地服务。

## 校验程序包

旁边的 `.zip.sha256` 保存整个 ZIP 的 SHA-256。PowerShell 可用 `Get-FileHash -Algorithm SHA256 -LiteralPath '2048-sandbox-v0.8.3.zip'` 对比；解压后可运行 `node scripts/verify-release.mjs` 检查清单中的文件摘要、长度和额外文件。

校验用于发现传输损坏和本地变更，未提供数字签名或发布者身份认证。第三方组件的版本和许可原文见包内 `THIRD_PARTY_NOTICES.txt`。

## 实测范围与边界

M6 验证覆盖 1,001 节点长链、宽树、平衡树，以及 50 对局／1,050 节点整库的回放、导出和独立副本恢复。长链保存后和重新打开时仍会完整回放，撤销栈随路径增长，可能需要数秒；实测不代表任意大小都能流畅运行。

当前支持最大 64 × 64 棋盘、九种技能、受控事件、规则版本和正式存档容器 v1。计时、保护格、非方形棋盘的 90/270° 旋转、未知能力只读导入、云同步与联网排行榜尚未开放。

开发者可使用 `pnpm test`、`pnpm test:e2e`、`pnpm test:performance` 验证源工程；程序包只需 Node.js，不包含源工程与测试环境。
